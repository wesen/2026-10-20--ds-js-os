# PicoCalc compiler research index and open directions

As of **19 November 2026**, the lab has two lines of compiler work. **CJI** compiles ordinary JavaScript using whole-program inference. The **typed compiler** checks a smaller JS-like language and emits Wasm or RV32 native code. The OS also runs QuickJS, which provides a bytecode baseline and executes the typed compiler itself. A result about one of these compilers does not automatically transfer to another. On the typed native path, streaming is the default at `7677932`. The physical Editor baseline for that algorithm is **2.452 s and 1,410,844 bytes peak QuickJS allocation**. [Production measurements](../../PICOCALC-COMPILER-INTEGRATION--integrate-qualified-compiler-optimizations-into-the-picocalc-toolchain/various/production-p4.json) · [Current compiler contract](../../PICOCALC-COMPILER-INTEGRATION--integrate-qualified-compiler-optimizations-into-the-picocalc-toolchain/design-doc/01-production-integration-of-the-typed-compiler-optimizations.md)

The independent RV32 studies use the streamed production compiler at `6426798` as their control. The primary physical run measured Editor at **2.484 s** for the control, **2.451 s** with branch fusion, **2.392 s** with compact words, and **2.336 s** with direct linked output. Direct output added 3,214 peak QuickJS bytes on P4. The candidates are isolated experiments. [Read the comparative report](../../PICOCALC-RV32-STUDIES--independent-picocalc-compiler-studies-of-branch-lowering-and-output-lifetime/analysis/01-how-a-handheld-compiler-spends-time-and-memory.md). ## The professor’s nine scopes

The plan makes **A the first, unconditional native-code scope**. Its earlier editorial proposal had gated native work on an input-latency measurement. The implementation plan moved that measurement into M. An unchecked task records the plan’s state when written. Later experiments sometimes answer part of a task using a different implementation or acceptance test.
