## 1. Errors and inconsistencies in the article

- **"It can turn `sw t0, 12(sp); lw t0, 12(sp)` into the store alone, and it cannot delete the store" (2/3: s1, s3)** reads as a contradiction. s3: the quoted rule says "The load can be replaced by a copy operation", so the article's own pair `sw t0, 16(sp)`, `lw t1, 16(sp)` saves nothing.
- **"the realistic gain is about half of it" (3/3)** has no stated basis. The record gives one: 7,490 pairs are 34.1% only if both instructions are counted, and only the load can go, so the ceiling is 17%. The row label hides this.
- **"the deepest operand stack in Editor is 8" against "The seven temporaries `t0`–`t6` are enough for almost all code" (2/3: s2, s3)**, while the model "assumes a free temporary register is always available".
- **Units (2/3: s2, s3).** "110 to 123 kilobytes, in a world that currently has 58 KiB": the saving is 107 to 120 KiB.
- **"The frame therefore need not be kept up to date between joins and calls" (1/3: s2)** reads as retracting the flush rule.
