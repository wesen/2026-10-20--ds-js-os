## 1. Errors and inconsistencies in the article

Each item was checked.

- **The §8.5 outline does not match its source (s1, s2).** `openFile.step(event, state)` calls `typedSdkFileRead(handle)`, but `handle` is neither a parameter of `step` nor a frame field. `case 1` tests `event.ok` where the source has `const ok = await ...`; §8.1 says only that the event "carries the same token".
- **One frame "suffices", then does not (s2).** §8.6: "one fixed frame per asynchronous function suffices"; two paragraphs later, "If an application needs two reads outstanding at once, it needs two frames". An acyclic call graph bounds nested activations on the stack, not instances suspended together, such as one callee awaited by two suspended callers ("what if the callee is already running?").
- **Tag mapping incomplete (3 of 3).** §8.3: "`readToken` being non-zero is tag 1, `unitsRead` and `unitsWritten` and `sourceLength` are the saved variables of continuation 2." The field that encodes tag 2 is never named. s2 and s3 call the numbering inconsistent; it agrees with §8.5 but reads as a mismatch.
- **"Only scalars cross a wait" (grader's check; flagged by s1, s3).** The parameter `state: WorldState`, a record reference, is used after both waits and is missing from the liveness table. The outline passes it again on each entry; the text never says so.
- **Name clash (grader's check).** "state.textLength = written; frame.state = 0".

Not confirmed: "71 state fields" does not conflict with "saves the same three" (s2).
