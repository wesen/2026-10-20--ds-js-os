### What didn't work

### What I learned

The tracked outputs depend on four inputs that are not in the repository:

1. **`src/render.js`.** `02-gen-kernel.mjs` calls `R.displaySource([])` for the post pass. Every generated C++ file carries render.js's SHA-256 in its header, and `lib/candela.mjs` `checkPin` requires it. The CANDELA-WORLD vendoring copied only the import closure of `candela.js` (15 modules), and `render.js` is not in it.
2. **`src/wgsl2glsl.js`**, which `render.js` imports.
3. **The gallery's presets with their `.md` frontmatter.** `loadPresets` reads `content/presets/*.md` for each preset's id and title, and the title is written into the scene table. The repository's `presets/` holds only the 28 T0 scene files, without `.md`. Of the 18 gallery scenes only B-01, R-01 and L-03 are T0; the other 15 were not vendored at all.
4. **The section API**, the 15 kernel functions the generated kernel exports. `02-gen-kernel.mjs` read them from CPU-KERNEL `various/01-section-api.json`, which `01-section-api.mjs` derives by building all 105 presets of the archive.

Why they were missing: `third_party/candela` was vendored by CANDELA-WORLD for the QuickJS world, which needs only the `candela.js` closure and the T0 scenes. The gallery's generators ran against the full archive in `/tmp`, and their outputs were copied in without their inputs.

The section API needs no new file. `translator/isa.js` already defines `SECTION_API`, with a comment saying it matches the kernel's manifest. It is the same 15 names in the same order as `01-section-api.json` `.api.fn` (checked: `same order: true 15 15`). The kernel generator can import it, so the kernel and the translator share one definition.

### What was tricky to build

- Two places bundle `third_party/candela` into the Candela world: `bundle.list` has `text-dir preset: third_party/candela/presets`, which bundles every file in that directory, and `text pin third_party/candela/PIN.json`. `runner.js` lists scenes as `Object.keys(pin.presets)`. Gallery presets therefore cannot go into `presets/` or into `PIN.json`'s `presets` map without changing the world's scene list and bundle.

### What warrants a second pair of eyes

- Deriving the section API needs all 105 presets. Re-deriving it is part of a Candela version bump and is not checked by `--check`.

### What should be done in the future

- Promote the upstream vendoring itself (CANDELA-WORLD `01-vendor-candela.py` and this phase's ticket script) to `tools/gen/candela/` when Candela is next bumped. It would also re-derive `SECTION_API`.

- Reproduction commands are above; the run root is `scratchpad/b2/run`, and the outputs are in `scratchpad/b2/ticket-kernel` and `ticket-gallery`.

### Technical details

## Step 3: Promote the generators to tools/gen/candela and pass the byte-for-byte gate

The generators became functions in `tools/gen/candela/`, called from one entry point, `regenerate.mjs`. The missing inputs were copied from the pinned archive into `third_party/candela` and pinned. With that, `--check` found all seven generated files byte-identical to the tracked ones. Only `VENDOR.json` changed, because it is rewritten.

### Prompt Context

**User prompt (verbatim):** see Step 1.
**Assistant interpretation:** Goals 1 and 2: promote, add one entry point with `--check`, and pass the gate without editing generated output.
**Inferred user intent:** Regenerate the firmware's Candela sources from the repository alone, and have a check that fails on drift.
**Commit (code):** `67ac952` — "gen(candela): promote the Candela generators to tools/gen/candela"

### What I did

- **Generators.** In `tools/gen/candela/`:
  - `kernel.mjs`: `generateKernel(root)` is CPU-KERNEL `02-gen-kernel.mjs` as a function. It takes `SECTION_API` from `translator/isa.js` instead of a JSON file, and returns the four files plus the WGSL it translated.
  - `isa.mjs`: `generateIsa()`, from SECTIONS `vm/gen-isa.mjs`.
  - `scenes.mjs`: `prepareScenes(root, gallery)`, from GALLERY `01-prepare-scenes.mjs`. Its constants (the scene list and the fixed-kernel SHA) are now data in `gallery.json`.
  - `lib/candela.mjs` and `lib/wgsl2c.mjs` come from CPU-KERNEL and `translator/*.js` from SECTIONS, copied with comment-only edits that point at their new neighbours. `lib/candela.mjs` `PIN` is unchanged, because `manifest.json` embeds it.
  - `package.json` makes `translator/*.js` ES modules.
- **Entry point.** `regenerate.mjs [--check] [--verbose]`:
  1. checks every file it will read against `PIN.json` (`modules`, `presets`, the new `generator.files`), and checks that `content/presets` holds exactly the pinned files;
  2. generates `kernel/{cdl_kernel.h,cdl_kernel.cpp,cdl_post.cpp,manifest.json,cdl_fixed_kernel.c}`, `vm/cdl_vm_isa.h` and `gallery/candela_gallery_scenes.c`, and checks that the scenes and the kernel come from the same `kernel.js`, as `02-vendor.py` did;
  3. writes `VENDOR.json`;
  4. without `--check`, writes what differs; with `--check`, writes nothing and exits 1 on any difference, a missing hand-written file, or a file in `kernel/`, `vm/` or `gallery/` that `VENDOR.json` does not list.
- **Missing inputs.** `ttmp/.../PICOCALC-REPO-LAYOUT--*/scripts/01-vendor-candela-generator-inputs.py ARCHIVE.zip [--check]` checks the archive's SHA-256 and reads its members with `zipfile`, extracting and running nothing. It checks that the archive's copies of the vendored modules and T0 presets equal the repository's. It then copies `src/render.js`, `src/wgsl2glsl.js` and, for every id in `gallery.json`, `content/presets/<base>.{md,js}` (38 files, 152 KB), and adds `PIN.json` `"generator": {"note", "files"}`. `PIN.json`'s existing text is preserved: the script checks first that it round-trips through `json.dumps(indent=1)`.
- **`VENDOR.json`** now has a note, the generator, the Candela pin, `fixedKernelSha256`, a table of input digests, and per file either `{"kind": "generated", "generator", "inputs", "sha256"}` or `{"kind": "hand-written"}`. The eight hand-written files are `kernel/{cdl_api.h,cdl_math.h,cdl_overrides.inc,cdl_post.inc,cdl_switches.h}` and `vm/{cdl_vm.c,cdl_vm.h,cdl_vm_ck_math.h}`, edited in place from now on. The note that sent edits back to the tickets is gone.
- **Drift test.** `ttmp/.../scripts/02-check-regenerate-fails.py` runs six cases: an edited generated file, an unlisted file, a changed pinned input, a missing hand-written file, an edited `VENDOR.json`, and a corrupted generated file that regeneration must repair.

### Why

- One Node process with generator functions, rather than a Python driver around four CLIs, keeps one loader instance and one pin check, and runs in 1.6 s.
- The gallery's inputs live in upstream's layout under `content/presets/`, so `loadPresets` is unchanged and the Candela world, which bundles `presets/`, does not see them. B-01, R-01 and L-03 are therefore present twice, as T0 scenes and as gallery inputs (three small files).
- The pins go into `PIN.json` under a new key, so the world's `pin.presets` stays the T0 list.
- The vendoring is a ticket script because it ran once. A future Candela bump should promote it (Step 2).

### What worked

- `node tools/gen/candela/regenerate.mjs --check --verbose` before `VENDOR.json` was rewritten printed: `differs ...: VENDOR.json` and nothing else. All seven generated files equal the tracked bytes. After `node tools/gen/candela/regenerate.mjs`: `1 of 8 generated files written: VENDOR.json`; then `--check`: exit 0.
- Each generated file's SHA-256 in the new `VENDOR.json` equals the old one's (for example, scenes `76184597…f40e`, `cdl_fixed_kernel.c` `d5503e45…b7ad`).
- `02-check-regenerate-fails.py`: all six cases print `ok`, and the tree ends with `--check` passing.

### What didn't work

- `python3 - <<'EOF' ... EOF`, used to apply comment edits, was refused by the worktree guard ("too complex to verify"). I made those edits with the editor instead.

### What I learned

- `cdl_vm_isa.h`, which the request lists among SECTIONS' hand-written files, is generated (from `translator/isa.js` by `vm/gen-isa.mjs`; its first line says "Do not edit"). It is treated as generated.
- `02-gen-kernel.mjs` also wrote `kernel.wgsl` and `post.wgsl`, and `01-prepare-scenes.mjs` wrote `scenes.json`. None of them was vendored. `generateKernel` returns the WGSL for inspection, and nothing writes these files.

### What was tricky to build

- A Candela file that is pinned but not read is harmless, but one that is read and not pinned defeats the pin. `loadPresets` reads every `.md` in `content/presets`, so `regenerate.mjs` also fails on any file there that `PIN.json` does not list. Case 3 of the drift test checks the other direction, a pinned file that changed.

### What warrants a second pair of eyes

- `VENDOR.json` digests cover data inputs, including `translator/isa.js`, which defines the ISA and the section API. They do not cover generator code (`kernel.mjs`, `lib/`, the rest of `translator/`). A generator change that alters output fails `--check` through the output. One that does not alter output does not touch `VENDOR.json`.
- The generated files still carry the ticket scripts' provenance text (for example, "Generated by 02-gen-kernel.mjs (PICOCALC-CANDELA-CPU-KERNEL) … Do not edit: change the generator, cpu/*.h or cpu/*.inc"), because the gate requires the tracked bytes. Changing that text is a separate generator change (see the next steps).

### What should be done in the future

- Phase G: run `node tools/gen/candela/regenerate.mjs --check` from `make test` (design Section 5.5).
