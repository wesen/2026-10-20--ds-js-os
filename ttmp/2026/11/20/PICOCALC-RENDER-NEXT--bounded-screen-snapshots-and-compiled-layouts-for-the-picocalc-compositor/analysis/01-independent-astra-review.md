# Independent review of the four renderer experiments

**Decision requested.** Fund a common measurement and correctness harness, then open two independent snapshot and template studies. Measure the opportunity for layout reuse and tile repair on the control before funding either prototype. Each experiment can lose without invalidating the others. An earlier System fix already runs on the playable handheld. A new design must improve a measured cost or establish a useful bound at an acceptable cost. The allocations below are proposed studies. This review inspected source and existing receipts at `12c76f876b14`. It contains no new device timings.

## Follow one update through the machine

Suppose a user moves from one System row to the next. The highlight may move within the same window, the window may scroll, the details below the table may change, and a clock or notification may change independently. These changes reach the LCD through several decisions.

```text
QuickJS System builds ui.* objects                  typed Editor writes UTF-16 JSON
prelude.__render stringifies them                   typedSdkScreen -> nw_screen
                  \                                 /
                   kernel compares and retains full frame
                     wraps sender/title, fans out copies
                                  |
               native event borrows (json, length, sender)
                CJI string conversion, parse, possible tree walk
                                  |
                   frames handler stores app state, queues draw
                                  |
                    measure -> raster back buffer -> commit
                                  |
                  display flush -> final SPI completion
```

System already limits Worlds to eight rows, Handles to fourteen, and keeps 48 graph samples. An inexact half-pixel case sends the original graph values to preserve pixel rounding. The prior physical qualification of `ef0ff95` ran for 152 seconds, obtained five CRC-verified captures and recorded zero faults or restarts. The older fault log contained two over-budget segments and two returns preceded by out-of-memory diagnostics. It leaves the failed allocation size and the time spent in decoding unresolved. The paired host figures of 4,016 → 1,766 bytes for Worlds are serialized tree sizes. The kernel envelope, memory high-water and SPI payload are separate quantities. [Producer](../../../../../../picocalc-os/js/apps/sysmon.js) · [Fault study and device receipt](../../PICOCALC-COMPOSITOR-FAULT--system-monitor-frame-faults-in-the-native-picocalc-compositor/design-doc/01-from-a-system-sample-to-a-panel-update.md)

In the native receiver, `cji_elf_event` already sees a counted payload. Reading field 2 through `rt_host_event` converts its UTF-8 bytes to a managed string. Generated `$message` then calls `$decode` **before** selecting the ordinary handler. Its text test for a backslash or `$h` can cause an additional recursive `$wire` traversal and allocation after JSON parsing. An escaped quote in a legitimate label is sufficient to enter that path. The kernel frees the mailbox message immediately after dispatch. A later self-addressed draw must own its snapshot or hold a reference to an immutable allocation whose reclamation is accounted for. An index built in the handler misses the cost that motivated the study. [ELF event](../../../../../../cji/runtime/cji_elf.c) · [CJI host event](../../../../../../cji/runtime/runtime.c) · [Generated receiver](../../../../../../cji/src/world-native.js) · [Kernel dispatch and replay](../../../../../../picocalc-os/nucleus/kernel.c)

## Allocate four experiments against one corpus

| Study and primary contrast | Available parallel work | Readout for the director |
| --- | --- | --- |
| A. Indexed JSON versus object decoding on identical complete envelopes. Keep engine, downstream widget coverage and pixel operations matched. If a C helper is necessary, call both treatments through the same boundary and report production CJI separately. | Own bounded ingress, lifetimes and a fixture reader. Give the other labs **semantic** test records before choosing an encoding. | Per-delivery decoder allocation, retained bytes, CPU to install a frame, worst segment and resulting pixels. |
| B. Template plus all dynamic values versus writing the same complete general snapshot. Hold layout and painting constant. | Use a hand-written template as a semantic oracle. A small extractor may target the same three System tabs independently of A's byte layout. | Producer time and allocations, wire bytes, receiver work, generated data/code and build cost, eligible-screen coverage, fallback frequency and costs. |
| C. Reusing measured dimensions versus fresh measurement on identical inputs and geometry code. | Use current objects or an oracle view, begin with reuse within one draw. Work in a fixture-owned scratch table before attaching it to A or B. | Measure calls, wrap calls, child visits and scratch high-water. Report time on mixed and all-invalid workloads, including lookup overhead. |
| D. Repair of conservatively damaged tiles versus full paint with the **same existing** band comparison and SPI policy. | Work from old and new oracle geometry and paint bounds. D can consume full layouts even if C fails. | Raster work skipped, repair overhead, final pixels, bytes compared, rectangles, SPI bytes/transactions, and terminal completion. |

An accepted snapshot makes A and B interoperable, but their host hypotheses have independent tests. B does not need CBOR. C does not need a compiler. D needs trustworthy old/new paint coverage and a fresh-layout fallback. It does not need a cache hit. If two treatments win independently, run a joint control, each single treatment and the combination on the same inputs before advancing. Charge the additional state in the combined build once. The effects need not add.

### A — Establish what “bounded” means

Test a span for each string/collection and a skip-to-end token for each nested value. A byte scan which repeatedly starts at the root can turn a row-by-column traversal into repeated parsing. Record bytes inspected, decoded scalars, scan steps and index bytes as input size and nesting rise. Keep field order semantically irrelevant. Specify treatment of duplicate keys and escaped names, nulls, floating-point values, unpaired surrogates, clipping and unknown widget fields against the oracle or a declared input contract. Test escaped and plain representations of the same scalar. The existing SDK helper assumes simple keys and maps non-ASCII Unicode escapes to `?`. This would change some displayed labels. The native `nat_json_ok` checks structure and wire markers, but supplies no offset index and gives no widget layout proof. [Small SDK helpers](../../../../../../picocalc-os/sdk/nw_json.h) · [Native JSON and screen validation](../../../../../../picocalc-os/nucleus/native.c)

“Zero-object” applies to UI-tree materialization on the defined receiver path. Existing CJI returns commit rectangles as JSON and allocates around graphics calls. Current producers, kernel wrappers, copies and framebuffers also allocate. Measure these separately. Propose fixed limits for encoded bytes, nodes, token count, depth, string bytes and decoded characters, array elements, table cells, draw operations and coordinate magnitude. A short line record with distant endpoints can make the existing line rasterizer walk a very long segment even when few pixels are visible. Include work bounds for loops that multiply two independently bounded quantities. Track the largest attempted allocation and any failure as well as charged memory.

The existing native limit is 16,384 bytes for tree and hints together. Ordinary retained posts have a 4,096-byte allowance which explicitly excludes frames. JavaScript producers have no matching native screen limit. There can be 32 worlds. Giving every world 16 KiB already consumes 512 KiB of raw backing before scratch, staging, queues or indices. Two 320 × 320 RGB565 buffers are another 409,600 bytes of system storage, with separate ownership. Report the actually simultaneous peak by memory owner/category plus a worst-case formula, including queued frames per subscriber, old and new generations, pins, resolver data, renderer state, and both buffers. Do not add unrelated counters as if all were simultaneous or charged to the compositor. [World limits and ownership](../../../../../../picocalc-os/nucleus/nucleus.h) · [DMA allocations](../../../../../../picocalc-os/nucleus/hw.c)

**Atomicity test.** Publish valid A, then over-limit B, restart the compositor, and inspect its first recovered focused view before publishing C. In the present kernel, `W->frame` already points to B by the time the receiver can reject B. A receiver-only atomic swap preserves A only until that receiver restarts. For the proposed last-good guarantee, validate and reserve space while A is still the durable generation, then atomically replace it. Keep A on rejection, count and surface the rejection outside the frame transport. If durable admission is outside the experiment, qualify only the local decoder and explicitly leave the cross-restart guarantee open. Repeat with two publishers, rapid replacement, publisher teardown and same-name restart. Verify that title, hints, template and snapshot all belong to the same authenticated publication and epoch. [Kernel retention and teardown](../../../../../../picocalc-os/nucleus/kernel.c)

The optional CBOR comparison gets a phase only if indexed-JSON profiling leaves substantial encoding, decoding or copying costs. Start with definite-length typed data, a frozen numeric/string policy and identical values. Run from the same counted byte boundary. Current native delivery calls `strlen`, and kernel messages use C-string copies. CBOR requires length-aware ownership, comparison, fan-out and replay through that whole path. Isolated codec throughput or an ASCII-wrapped prototype answers a narrower question. Charge wrapper cost and postpone a transport experiment when it cannot fit the agreed scope. [Native dispatch](../../../../../../picocalc-os/nucleus/native.c) · [CBOR data model and lengths](https://www.rfc-editor.org/rfc/rfc8949.html)

### B — Measure specialization and its coverage

Use a single immutable template ID for each supported shape and send every current dynamic value on every publication. For a single table, the template may know the headers, fixed widths, alignment and font. The values include the visible rows in order, their local selection and any colors or optional strings. A background app can become visible immediately from one retained publication. Build-time identity must include the version of the resolver or a content identity shared by producer and receiver. Try a cold receiver, a mismatched ID, a loadable app with no known template, an empty view, and a switch from Worlds to Handles where the number of columns changes.

The JS prelude flattens children, filters null/false, and uses `Object.assign` for options. In System, options include spreads, tab-dependent branches and dynamic colors, and the Buses view has an empty alternative. Restrict the first compiler proof to identifiable pure builders, constant property names, statically bounded repeated slots and explicit sum cases. Preserve evaluation order and count for all dynamic expressions; calls may observe state. Classify unsupported code, report it and run it by the existing complete-snapshot route in the experiment. A hand-written template informs the upper bound. Count how often the extractor attains it on the preselected unseen **Keys** JS builder producer. Its nested row, box, key-value pairs and key history offer another real source shape. [Keys](../../../../../../picocalc-os/js/apps/keys.js) [JS builder semantics](../../../../../../picocalc-os/js/prelude.js) · [System tab builders](../../../../../../picocalc-os/js/apps/sysmon.js)

Typed Editor writes counted UTF-16 JSON into a buffer, uses a 36-row position window and emits up to 17 document rows. A preview switches widget kind, finding removes the cursor and adds marks, and asynchronous work may delay frame publication across turns. `typedSdkScreen` transcodes to UTF-8 and calls `nw_screen`. A JS-AST extractor cannot recover a `ui.table` call that never existed here. Keep Editor's producer unchanged for the held-out consumer test. If someone later prototypes an explicit typed template emitter, its writer/SDK change has its own cost and qualification. It cannot substantiate general JS extraction. [Typed row navigation](../../../../../../picocalc-os/worlds/editor/view.typed) · [Typed frame writer](../../../../../../picocalc-os/worlds/editor/document-view.typed) · [Shared SDK](../../../../../../picocalc-os/sdk/typed/world.c)

### C and D — Geometry, paint order and recovery

Within a frame, key an intrinsic measurement by node occurrence, width, font metrics and all other relevant constraints. Reuse a size only while these inputs are fixed. `rowWidths` divides leftover space among flexible siblings. `stack` uses aggregate grow values, gap and parent height to decide each child's final rectangle. A narrow text change can move siblings while their intrinsic measurements are reusable. Store **measurements** and **placement** as distinct results. Across frames, compare geometry-affecting inputs exactly or verify a fingerprint hit. A pointer into an old byte snapshot and a colliding hash are both insufficient. Qualify dynamic color-only updates, equal-length strings whose spaces wrap differently, a width change, insertion/removal and all-miss churn. If cross-frame retention costs more than remeasurement, retain the bounded within-frame result. [Compositor measurement and placement](../../../../../../picocalc-os/js/system/compositor.js)

For repair, define the changed region from the old **and** new painted extents. A border drawn one pixel outside a canvas and a graph's second parallel stroke are concrete examples of pixels outside a naive interior. A translucent glyph blends with its background. Erase each dirty region back to its correct background, then repaint all intersecting layers in their original order with a real clip or an equivalent bounded offscreen mechanism. Testing intersection only decides *which* primitive to run. It cannot prevent that primitive from redrawing outside the damaged region. An unchanged sibling beneath a disappearing banner must be repainted. Focus changes, cache ambiguities and a lost display can request full-screen repair. [Paint order, canvas border and graph stroke](../../../../../../picocalc-os/js/system/compositor.js) · [Glyph blending and primitive clipping](../../../../../../picocalc-os/nucleus/gfx.c)

```text
change    = old painted bounds ∪ new painted bounds
dirty     = tiles covering change, plus pending chrome or recovery damage
for each nonoverlapping dirty region:
    restore background, clip to region, replay intersecting layers in z order
commit    = existing 16-row-band RGB565 comparison
flush     = send commit rectangles, observe each job's outcome
on lost panel state:
    mark all tiles pending and arrange a complete re-presentation
```

A 16 × 16 candidate grid is 20 × 20 tiles, requiring 50 bytes for one packed bitmap. Geometry history, per-tile contributor indices, a clip stack and overflow handling can dominate that budget. Full repaint already uses changed-rectangle delivery. Choosing fewer tiles may save CPU and still send the same SPI bytes. Only the final comparison decides what to send. `gfx_commit` copies changes into front **before** the display confirms the transfer; a front-buffer checksum alone can pass while the panel is stale. Existing skip/error paths invalidate the comparison buffer; a candidate that early-exits on an empty logical dirty set must honor this invalidation even when app state is identical. The SPI worker pins the buffer object and reads its front pixels while transferring. Preserve single-writer sequencing or keep an immutable flush generation until completion. [Band commit](../../../../../../picocalc-os/nucleus/gfx.c) · [Display protocol](../../../../../../picocalc-os/js/drivers/display.js) · [P4 worker](../../../../../../picocalc-os/port/esp32p4/main/bus_p4.c)

## Measurement contract and release gates

1. **Freeze inputs before tuning.** Record quick System transitions, several stationary samples, scrolling/clamping at both ends, near-half graph samples, empty/cold startup, identical repost, background publication and return. Include clock, battery, focus, banner, hints, selected row and timer ordering. Freeze samples in both timing arms. A faster implementation changes the CPU and bus counters visible on the live System screen. Demand deterministic pixel equality on the frozen run; check live semantics, progress and health in the normal boot separately.
2. **Use the right oracle.** For A–C compare geometry, drawing operations where applicable, and full RGB565 bytes after every frame. For D, legitimate candidates omit operations. Compare the complete composed framebuffer to an independently full-painted buffer, separately verify that applying returned flush rectangles to a simulated panel reconstructs it, and retain a first-pixel mismatch with frame ID, rectangle and layer. Verify the real driver’s completion and bus counts separately. Carry ordinary sender, focus, overlay and restart behavior through both controls.
3. **Measure causal chains.** Track app event → eligible render → publication → arrival → adopted generation → queued/coalesced draw → framebuffer commit → final matching SPI job. Report identical-frame suppression, superseded frames, no-pixel changes, offscreen frames, queued draws and missed samples. Only a sample that caused pixels has a terminal SPI time; report the others with counts and appropriate terminal events. Keep internal kernel-to-SPI intervals distinct from physical key closure and LCD response, which require external instruments. The existing scope M1's 20-ms quiet heuristic is ambiguous with background updates. Tag matching work or mark ambiguous samples explicitly. [Native roadmap M1/M2](../../../19/PICOCALC-NATIVE-NEXT--a-smaller-rv32-backend-a-module-cache-safety-checks-and-await-for-typed-picocalc-worlds/design-doc/08-scopes-m-and-h-the-key-to-frame-measurement-and-later-items.md)
4. **Set admission criteria before opening the held-out data.** Require zero pixel/ownership/replay discrepancies, zero unexplained frame loss, zero bus errors or faults under unchanged limits, and no accepted input beyond the declared budgets. Fit the performance floor on repeat control/control sessions, record a minimum worthwhile change for each primary metric, then lock it. Use paired alternating build order across independent boots, report each boot's paired differences as well as p50/p95/max, record counts, run durations, build IDs and trace overhead. Avoid treating multiple frames from one boot as independent boot replications. Unresolved effects within drift stay inconclusive.
5. **Unlock Editor once.** A separate evaluator runs predeclared ordinary edits, cursor movement, find highlights, wrap/cross-line navigation, long Unicode and Markdown-preview scenes, plus a close/return/restart flow. Check cursor position, hints, saved content, per-frame pixels and recovery. Freeze the producer/manifest, performance rules and data hash beforehand. A failure is a held-out result. A revised candidate gets a new revision and a fresh validation split. Publish a negative result or an expensive fallback with the affected frame and caps. One operator owns physical qualification and restoration of the current playable image.
6. **Stop or promote by cause.** If A cannot bound retained and in-flight memory in the named scope, keep its scanner measurements as a host experiment. If B's unsupported cases dominate or its costs erase producer savings, keep general snapshots. If C’s invalidation or D’s region repair cannot preserve pixels, fall back to fresh layout or full paint. Promote an individual engineering change only after its combined candidate clears the same gates. Host virtual time is unsuitable for a speedup claim in particular here: `gfx_commit` charges the whole panel's nominal diff cost independently of how many bands it inspects. Record actual CPU/cycle or wall-clock deltas on P4. [Graphics accounting](../../../../../../picocalc-os/nucleus/gfx.c)

## Consolidated reading and deferrals

| Principle | Mechanism to borrow and the experiment it informs |
| --- | --- |
| Tokenization and lifetime | jsmn records token boundaries into caller-owned input. Use its offset idea in A, add direct subtree skips and explicit buffer ownership, and measure scanning work. simdjson's on-demand traversal provides a contrast for replaying repeated access; its desktop performance cannot predict P4 timing. [jsmn design](https://github.com/zserge/jsmn) · [simdjson traversal](https://simdjson.org/api/2.0.0/md_doc_basics.html) |
| Partial evaluation | A known part of a program can specialize the work that remains for dynamic values. In B, keep immutable shapes separate from current complete values. Vue's compiler illustrates classification of static output and dynamic fields. Its retained DOM and patch protocol do not supply the required replay contract here. [Jones, Gomard and Sestoft](https://raspi.itu.dk/people/sestoft/pebook/pebook.html) · [Vue rendering mechanism](https://vuejs.org/guide/extras/rendering-mechanism.html) |
| Access by validated offsets | FlatBuffers' layouts illustrate fixed fields and offsets into an immutable buffer. Use this as a reference for slot layout and size accounting in B. Full adoption of a schema toolchain is a separate decision. [FlatBuffers internals](https://flatbuffers.dev/internals/) |
| Dependency-sensitive measurement | Yoga skips clean subtrees under unchanged parent constraints, giving C a precise test for width and parent changes. Acar's change propagation explains why recording dependencies itself costs time and space. Begin with fixed entries and a dense-update control. [Yoga incremental layout](https://www.yogalayout.dev/docs/advanced/incremental-layout) · [Acar, Self-Adjusting Computation](https://www.cs.cmu.edu/~rwh/students/acar.pdf) |
| Old and new damage, ordered repair | LVGL documents saving both extents and redrawing the affected layers. Apply this in D to opaque backgrounds and alpha glyphs, retaining the existing commit and flush logic as the comparator. [LVGL 8.4 drawing documentation](https://docs.lvgl.io/8/_downloads/39cea4971f327964c804e4e6bc96bfb4/LVGL.pdf) |

Defer a general JS partial evaluator, dynamic dependency graph, general constraint solver, SIMD port, binary patch-chain protocol and display-driver rewrite. The first four become relevant only if their respective bounded experiment exposes a concrete missing capability or bottleneck. A patch-chain protocol would change the independently replayable frame contract. A display-driver study needs evidence that matched SPI bytes or transaction scheduling dominates the remaining latency. These are reopening conditions inside the four studies, with results reported to the same director.

## Disposition of the commissioned Opus draft

I compared the commissioned design (public response digest `c7d704f3d105…`) and its companion literature memo with the available source. The guide's explanations of static/dynamic inputs, independently replayable snapshots, sender checks and typed Editor's distinct frontend belong in the roadmap. The authoritative phase and budget decisions are the director's. The following amendments were sent to the director before publication. [Design](../design-doc/01-a-bounded-screen-renderer-from-producer-to-panel.md) · [Director's phases](../design-doc/02-lab-phases-independent-studies-and-device-qualification.md) · [Survey](../design-doc/03-research-families-primary-sources-and-promotion-criteria.md)

| Draft issue | Disposition and deciding evidence |
| --- | --- |
| A predicted mask must cover every returned commit rectangle, and a miss is a failed renderer. | **Replace the oracle.** In a single band, two changed pixels at opposite horizontal edges yield a wide transfer rectangle spanning unchanged pixels. A repair mask containing just those two tiles may be exactly right. Test every actually different pixel for membership, compare final full RGB565 bytes, and apply candidate flushes to the simulated panel. Rectangle equality can remain a diagnostic when both arms use identical comparison state and policy. |
| The present compositor tracks old/new geometric damage; several geometry helpers individually remeasure subtrees. | **Correct the baseline.** The `frames` handler stores the latest tree. Its subsequent `draw` performs full painting followed by a pixel comparison. Recursive visits arise through `measure`, `measureStack` and the measurements started by `stack`. `rowWidths` computes widths, and `drawTable` paints from supplied geometry. |
| A selection is a list containing title and clock, affecting just two painted rows. | **Use the real example.** System Worlds has a seven-column table, a graph and selected-world key/value details below it. The compositor owns the wall-clock display. System displays uptime in its own tab row. Keep proposed rectangles illustrative, freeze independent inputs, and include the selected-world details and possible centered scroll in damage. |
| The draft leaves framebuffer quota open and records a per-category peak. | **Trace the allocator.** The CJI graphics syscall hands dimensions to kernel `dmabuf_alloc`, which allocates two 204,800-byte planes using P4 `port_big_calloc` in PSRAM. These system allocations bypass the ELF world's `m_malloc` charge and are released on last handle/pin. Record simultaneous total peak and ownership, separately from the world's quota reading. [Kernel allocation](../../../../../../picocalc-os/nucleus/hw.c) · [P4 allocator](../../../../../../picocalc-os/port/esp32p4/main/port_p4.c) |
| A bounded token array makes string handling free, definite CBOR lengths reveal every item's end, and corpus maxima set the budgets. | **Specify the validated domain.** Indices avoid eagerly copying strings into the tree. Escaped text may still require bounded decode and temporary storage at draw time. A CBOR array header gives an element count. Variable-size descendants determine its byte extent. Set byte, work and simultaneous retention caps from platform headroom and the promised input contract. Use the corpus to check coverage. |
| Recipients can request an unspecified full-tree fallback after failing to resolve a template. | **Close the restart path.** Bind descriptors to the installed image, check availability when admitting a durable record, and define the miss/retry path. The previous approved snapshot must survive an unknown ID. After a cold restart an idle producer may never send another screen. Distinguish existing behavior from these proposed admission and diagnostic guarantees. |
| The guide's local T0–T8 sequence, an unchanged-only template control and layout-cache dependence for tiles compete with the phase plan. | **Use one authority.** The director's P0–P4 determine gates and assignment. Keep generic, manual and automatic complete representations on identical suppression rules and both changed and unchanged transitions. Use a same-language/backend materializing control if moving parser implementation into C. R3/CBOR and cross-frame reuse stay conditional. Tile repair can use fresh geometry. Freeze Keys for extraction and typed Editor for a consumer-only hold-out. |

The literature memo's full-panel flush baseline, automatic rejection when an index exceeds wire size, and p99 estimates without sufficient independent support do not enter the protocol. A measured, affordable index may exceed the size of a compact input. The original band comparison already suppresses many SPI writes. The number of independent boot blocks and paired within-boot sample count determine what tail or uncertainty can be stated.
