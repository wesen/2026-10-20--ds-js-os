Context and blind proposal: The PicoCalc panel is 320×320 RGB565. Ordinary apps emit complete immutable screen trees, the kernel currently stamps sender and title in NUL-terminated JSON, and the CJI compositor stores the last tree and paints. The proposal before timings was UITB with aligned 8-byte slots, sorted field IDs, block starts indexed during verification, optional resident dictionary, exact-F32-or-reject numeric rule and optional dedup/typed vectors. It expected at least 20% larger wire for its dictionary arm in all four workloads, two-generation peak at most 60% of JSON, and little gain where paint dominates. Do not imply those predictions were tested identically. PSIX v1 implements the direct array/static-slot and sorted map ideas, with 3-byte slots, binary64 numeric fidelity for real floating values and strict body preorder. It has no app-specific resident dictionary, no shared subtrees and no delta. Typed transport remains unimplemented. A receiver view cannot outlive its owned immutable bytes. Each Array has a u16 count then 3-byte refs. Object count is u16 then (u16 key ID, 3-byte ref), sorted by key ID. Reference has 4-bit tag and 20-bit operand. Byte 10 holds root ref; header + UTF-8 dictionary (strings deduplicated per packet, offset table with sentinel) is followed by body. Noninline child-body offset must equal next unconsumed body position during validation. Sorted in-frame UTF-8 string directory and object key IDs support field binary search. Direct array index uses start+2+3*i. Worked example encode {"kids":[{"t":"label"},{"t":"gap","h":2}]}. String IDs gap=0 h=1 kids=2 label=3 t=4. Root object starts byte 39 with field kids referencing array at 46. Slots at 48,51, latter points to second child at 61. At 63 key ID h=1, inline integer at 65 is 2. First child's body at 54 is irrelevant to selected access after admission. Cost is 73 bytes. Official precedent FlexBuffers format internals https://flatbuffers.dev/internals/ uses direct vectors, sorted maps, variable widths and offset directions of its own. PSIX caps 32768 wire bytes, 24 levels starting at depth 0, 8192 values, 1024 items/64 fields per collection, 4096 unique strings, 2048 UTF-8 bytes per string. Structural and sender-envelope validation only. A host last-good test retained accepted bytes against wrong sender, malformed candidate and stale generation, with an old view pinned while a new frame replaces it.
