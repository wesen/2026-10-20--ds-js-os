# Feed the visible board from packed ground vertices

The scalar scene projects the four corners of each tile independently. Adjacent tiles share corners, so a 9 by 9 ground lattice can supply all 64 tile quads with 81 projected points. This experiment routes those repeated corners through the existing automatic PIE fixture. Pieces and the extruded bottom edge still use the scalar projection because their vertices have different heights.

## Source and ABI

The experiment builds a private source from `scripts/scene/isometric.typed` and the unchanged `01-vertices.typed` in the PIE research ticket. The frozen scalar scene remains the control. The alternate entry takes exactly eight register arguments.

```text
paintChess(state, out, xs, ys, zs, sx, sy, depth)
```

The first two buffers retain the current 90-cell state and 4,096-word drawing layouts. The private runtime allocates six distinct internal scratch buffers. Each has at least 82 addressable halfwords, a four-byte capacity immediately before its payload, and a 16-byte-aligned payload. The buffer lifetime belongs to the loaded painter. The kernel is its sole caller.

The Typed painter fills elements 0 through 80 from ground coordinates `x=16*(i%9)`, `y=0` and `z=16*(i/9)`. The host sets camera pitch in `ys[81]`. For each vertex, the unchanged projection result is `sx=384+x-z` and `sy=640+x+z`. The visible camera coordinates follow from

```text
u = sx - 224
v = 42 + (sy - 640) * pitch / 8
```

This reproduces the scalar integer operation order for ground vertices. A tile at `file,rank` reads indices `j`, `j+1`, `j+10` and `j+9`, where `j=rank*9+file`. The top of the board lip also uses lattice indices 72, 80 and 8. The depth channel is written by the shared projection routine and remains available for geometry experiments. The existing scene's draw order continues to use diagonals of the logical board.

## Match the render and observe the vector path

Recompile and compare the frozen scalar Wasm, alternate Wasm, and packed RV32 commands and final raster bytes across the 47 position fixtures and pitches 3, 5 and 7. The oracle should also check that the alternate scene writes 30 vector stores, ten groups of three, before completing a one-vertex scalar tail. Comparing an unaligned scratch layout with aligned scratch verifies the ordinary fallback on the same visible workload.

The witnessed device firmware adds a private backend operation after the successful packed loop, gated by the exact allowlisted module, function signature, 81-vertex count and depth capacity of at least 82. It writes a tag to `depth[81]`; the loaded painter clears that slot before every call and records its value after return. The tag is outside geometry and outside the first 81 cells. The separate uninstrumented compiler retains its ordinary Typed semantics and writes no witness. Physical timings from the witnessed image include that operation.

The cold build comparison must track generated bytes and the app-side source identity. Per-frame timing includes lattice construction, projection, tile commands and remaining scalar geometry. Packing changes the scene's geometry reuse as well as code generation, so use the alternate source with PIE disabled for a like-for-like projection study when available. A board renderer with fixed camera geometry could instead retain these screen coordinates across state updates.

## Build and reproduce

The paired firmware keeps the eight-argument ABI throughout the C wrapper, loader, and reactor. The stage compiles the delivered source into three self-contained images, each with zero imports, and concatenates them in one 48 KiB private executable slot. Internal calls and jumps are relative to the instructions that issue them. The reactor publishes three pointers for the witnessed, raw PIE, and guarded RV32 entries. The production scene and slot are outside the staging directory.

```bash
bash scripts/packed/04-build.sh /tmp/chess3d-packed \
  /tmp/pico-snake-production/tree/picocalc-os/port/esp32p4/dependencies.elf.lock paired

node scripts/scene/linked.mjs /tmp/chess3d-packed/tree \
  /tmp/chess3d-packed/tree/picocalc-os/worlds/chess/painter.typed \
  /tmp/chess3d-packed/build/esp-idf/main/mobile-painter-slot.elf \
  /tmp/chess3d-packed.elf
```

The C wrapper owns one 1,152-byte, aligned allocation in internal RAM for the six slots. Each struct has a 16-byte header footprint, including its capacity at offset 12, and a 192-byte stride. The caller supplies capacity 82 and the layout leaves room after the reserved cells. The console queues a flag for the same kernel lane that owns the live scene. The kernel's ordinary drawing turn needs only the witnessed call. The guarded and raw entries run only when that console flag is consumed. No benchmark changes the retained output list.

```bash
python3 -B scripts/packed/05-device.py /tmp/chess3d-packed-observed \
  /tmp/mobile-painter-production/build /tmp/chess3d-packed/build \
  /tmp/chess3d-silhouette-raster \
  /tmp/chess3d-packed/tree/picocalc-os/worlds/chess/painter.typed \
  /tmp/chess3d-packed.elf --preflight
```

Preflight checks the release identity and the candidate's geometry without opening serial. Reproduction requires the board operator's handoff. Run the same command without the preflight flag to take the shared serial lock, capture the witnessed scene and compare raw PIE and guarded scalar output, then restore the verified playable app. The 14-second compilation allowance applies to the private triple-build lane. Its observed installation latency should be reported separately from a single ordinary source build.
