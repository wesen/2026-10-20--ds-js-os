- Goal: fix opening the System monitor on the ESP32-P4 PicoCalc and preserve the current playable firmware. Two Opus High roles reviewed the frame producer and receiver independently from bounded evidence. The supervisor implemented changes, ran the host comparison and operated the board.
- Source: picocalc-os/js/apps/sysmon.js reads the world list and handles while focused, samples every 500 ms, and keeps 48 graph samples. User can select all rows. picocalc-os/js/system/compositor.js receives frames, verifies the sender, retains the latest tree and coalesces repaint requests. A separate draw event measures and paints the focused tree into a 320x320 framebuffer. Changed rectangles are flushed via picocalc-os/js/drivers/display.js to the panel over SPI. A frame fault does not time the SPI transfer.
- Original board: native compositor in natives/compositor.elf generated from JavaScript by CJI, interpreted JavaScript monitor. Time budget 80 ms, memory quota 768 KiB. Generic loader in picocalc-os/port/esp32p4/optional/native_elf/native_elf_p4.c calls module, checks time first, accepts 0 (NW_DONE) or 1 (NW_LATER: deferred reply); it REJECTS 2. No evidence of false success in the loader. Never clamp 2 to 1. Runtime in CJI import runtime/cji_elf.c deliberately returns 2 on fatal; two raw serial lines say compositor: crashed: out of memory, each 1.3 ms before end-of-2 faults at uptime 39.836 and 53.336 s. Two additional frame events (30.419 and 31.763 s) exceeded budget, without a preceding OOM in the capture. The returned-2 records were at 512 KiB, budget-only records at 504 KiB. Exact failed allocation and timing component unmeasured. A refused allocation does not add to charged usage. Cannot claim fragmentation, specific collector growth or common cause as proved.
- Fix df79a0f: publish a centered eight-row window for Worlds and fourteen for Handles (enclosing windows, not necessarily visible counts), translating selection to a local index while keeping the entire source model and selected details. Start = clamp(sel - floor(capacity/2), 0, max(0,count-capacity)). Eight uses offset 4; fourteen uses 7. The global row 20 of 28 yields rows 16..23 and local index 4. Rendering six rows starts at global row 17. Tabs, update frequency, all rows and both graphs preserved. Graph maps each normalized sample to the integer distance from its baseline, scale = height - 3; labels continue to use original counters. No kernel ABI or memory/time budget changes.
- Source test: compare two versions of the app screen function on identical state, feed the resulting trees to the original compositor's draw at x8 y28 width304 height270. Capture ordered FB calls and arguments. On synthetic fixtures across 28 Worlds and 36 Handles selections and one Buses selection: zero drawing differences, tree bytes at final selection 4016 to 1766 (-56.0%), 2641 to 1529 (-42.1%), 2678 to 1166 (-56.5%). These are synthetic JSON tree bytes, not measured heap bytes or real serial packet lengths. A fixture has 36 handles; that is not the observed real number.
- Producer review proposed half-pixel stress tests and short table cases. Supervisor implemented them: a new test found a one-pixel line mismatch. Native renderer rounds absolute screen y after subtracting the fractional offset, while the first candidate rounded the offset alone. ef0ff95 preserves original operands for an entire graph when an inexact offset lies within 320*Number.EPSILON of a half. An exact half follows the established tie rule. 69 extra host boundary comparisons then passed. No fragmentation or allocator rollback fix shipped. The receiver review recommended physical evidence of active progress beyond no fault messages, adopted by supervisor; incorrect proposals to reinterpret code 1 were rejected. Reports should make clear what the evidence actually proves.
- Physical experiment on first candidate df79a0f, same 80 ms and 768 KiB limits: 152-second scheduled capture. Compositor advanced 181 to 1256 turns, System 92 to 419. Three complete world snapshots, zero new logged faults or restarts. Four CRC-checked, visually inspected frames show System Worlds with keyboard selected, last world nat-dial selected after 30 Down keys, Handles, and Buses. Final Chess screen had a corrupt initial serial capture and was successfully recaptured separately. The focused Worlds screen showed six visible rows. This is a direct physical outcome, not an estimate of mean receive time. Tests did not establish the specific allocation, exact component timing, an unbounded guarantee or an SPI speedup. A separate repeat on the half-pixel-corrected ef0ff95 firmware is being operated by the supervisor and will be reported in the supervisor's synthesis. Scope your own board claims to df79a0f.
