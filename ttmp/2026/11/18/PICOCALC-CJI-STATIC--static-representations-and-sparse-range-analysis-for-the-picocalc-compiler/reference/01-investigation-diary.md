# Investigation diary

## Step 1 — Reattach the board and locate dynamic calls in the self-hosted compiler

The device test compares the previously qualified guarded build against its exact ordinary headless control. Host instrumentation runs independently on the guarded x86 stage 1. Keeping those experiments separate allows us to change the instrumentation without changing the firmware under test.

**Assistant interpretation.** Run the existing candidate on the board while researching further optimization. **Inferred user intent.** Reduce the time a user waits for a verified module, with a design that a newcomer can implement and evaluate.

### What I did

- Started script 01 in tmux. It uses the previous PERF ticket's flashing, boot checks, module validation and restoration. Its fresh output directory keeps the previous interrupted run intact.
- Linked counters into the guarded native compiler. Scripts 02–04 track direct calls from generated code. Scripts 05–06 count actual branches in a separate copy of the runtime. Script 07 isolates the receiver of one highly executed library helper.
- Read the local textbook's data-flow and SSA treatment, primary papers on type constraints, constant propagation, widening and versioning, and CJI's inference, lowering, library and runtime sources.

### Why

The previous CPU timer reported the executing instruction. Many passes share the same runtime helpers. Naming the compiled callers and measuring receiver classes gives a testable alternative to changing the runtime indiscriminately.

### What worked

The device booted with idle compiler and zero keyboard/display bus transfers, and compiled the Flaky smoke world. Both standalone native counter builds emitted the exact reference Agenda and Files SLIR. The leading index caller in each was the same slice specialization. A third diagnostic isolates that call site.

### What didn't work

Serial discovery inside the filesystem sandbox returned “No such file or directory” for /dev/serial/by-id. The host check found the expected adapter, serial 5B61091051, attached as ttyACM0. No device restart was needed for discovery.

### What I learned

A dynamic call can combine independent unknowns. The Agenda slice loop already carries an integer index. Its generated code boxes that index to satisfy the dynamic receiver ABI. A known array layout would allow a simpler access even if every element still needed a dynamic tag.

### What was tricky to build

A linker wrapper observes external generated calls, while a runtime helper can call another helper internally. I measured those populations separately. Address resolution subtracts one byte from the return address and checks the symbol's actual size. The extra-property counters distinguish an absent extras array from a scan that examined entries.

### What warrants a second pair of eyes

Check that a proposed specialized read preserves the generic missing-index result, hole handling, element layout and collection roots. Counts collected under instrumentation describe workload frequency. They are insufficient to infer elapsed time saved.

### What should be done in the future

Run a differential prototype only after specifying the static proof or runtime guard. Measure emitted code, output behavior and physical compile latency independently.

### Code review instructions

Start with scripts/03-measure-sites.sh and 06-run-probes.sh. Both accept the named-object directory from RANGES script 34 followed by a new scratch directory. Each checks generated bytes before reporting. Script 01 takes a new output directory and the immutable firmware snapshots.

### Technical details

Both host compilers used compacting GC and an 8,388,608-byte heap. Symbol names include a canonical suffix which distinguishes specializations with the same source name. The board compares complete linked modules against the independent catalog reference.

## Step 2 — Explain where the repeated indexing and joins originate

Step 1 identified a hot slice loop. I inspected the compiled helper, traced the numeric analysis at source level, and changed the design's priority after finding the persistent-state writer. It can copy an entire 32-slot trie node even when a write assigns the existing interval. Avoiding that copy would also preserve subtree identity for future merges.

### Prompt Context

See Step 1. The question was whether a small program really requires this much dynamic representation and interval work. Commit 14677c7 records the first instrumentation checkpoint.

### What I did

- Counted direct join consumers under Node, reproducing all 3,036,247 joins on Agenda. Counted unchanged writes and shallow-equal merge results without substituting any return values.
- Ran three rotated rounds of sidecar creation and strict replay on each world. Verified every byte of generated SLIR and every sidecar entry. Added a runnable three-function example demonstrating integer, floating-point and dynamic addition.
- Read the implementations alongside the algorithms in Cooper and Torczon §§9.2–9.4, Palsberg and Schwartzbach, Wegman and Zadeck, Cousot and Cousot, Bodík et al., Chevalier-Boisvert and Feeley, and Braun et al. Compared each algorithm's model with the actual language and memory budget of CJI. Rendered the guide diagrams from script 09.

### Why

The slice receiver census can justify a new guard. It cannot tell whether the source program needed to copy any elements at all. The additional measurements distinguish eliminating an unnecessary state update from accelerating the dynamic operations it causes. Sidecar measurements distinguish recording cost from savings on an unchanged source.

### What worked

Agenda assigned an unchanged interval in 194,247 of 490,367 local state writes. Merging local states accounted for 1,826,045 joins. The source-level 496,705 copies of 32-slot arrays account numerically for almost the entire 15.92 million dynamic index reads observed in the generated slice body. This is corroboration across executions; the scripts do not match individual copy events. Strictly verified Agenda sidecar replay was faster on the host, but recording was sufficiently expensive to take roughly six subsequent cache hits to break even at these medians.

### What didn't work

Script 11 first rejected its source hooks with “unexpected number of source sites: 9”. Reviewing the actual calls showed nine sites including the callback supplied to merge. The next attempt reported “TypeError: compileSource is not a function”; the public source-level entry used by the previous profiling harness is in src/build.js. After both corrections the counts reproduced the control and output equality on both inputs.

### What I learned

The slice dispatchers split out strings before reaching the measured loop. Their remaining branch does not establish array layout on its own. CJI already interns intervals and widens progressively. A new proposal should leverage the stable interval identity across persistent-state updates within one analysis.

### What was tricky to build

The scope of a counter matters. A function-level inclusive instruction count includes its children. A direct call count from a compiler helper does not. An equal child array result can be tested shallowly in the diagnostic run without changing the identity of the result returned to the existing solver. The proposed production change needs observable equivalence when catch blocks retain shared mutable state handles.

### What warrants a second pair of eyes

Audit the exact definition of uninitialized slots and interval ID lifetime; verify negative zero, NaN, helper specialization, exceptions, roots and unknown callers. Confirm the proposed SD driver path physically on this carrier before treating the card as an available pass store.

### What should be done in the future

Compare an unchanged-write prototype against the guarded control. Measure a receiver-specialized loop separately. Track both on an unchanged source and after a local edit; measure proof-file recording overhead, verified replay and rejection of a stale entry.

### Code review instructions

Inspect the records in various/agenda-{join-sites,state-copies,slice} and the experimental scripts 07, 08, 11 and 12. In the guide, follow the slice example through to the persistent-state copy count and inspect the independently executable three-additions example. Script 09 regenerates both figures.

### Technical details

The Node observers only wrap source transfers or inspect the resulting 32 slots. Their elapsed times would be distorted. The independent sidecar timing script runs a clean Node process for each measurement. A measurement of native x86 instructions for the entire named slice function was started separately with Callgrind.

The completed independent Callgrind run attributed 34,472,179,959 of 49,355,143,290 guarded Agenda x86 instructions to analyzeRanges including callees (69.85%). Files was 39.36%. The named slice alone accounted for 8.73% and 3.78% inclusively. This resolves the earlier uncertainty about whether range analysis remained important after reducing its full analyses from seven to two. The categories overlap. Script 15 separately recorded the actual file-store traffic under Node: 593 append operations and 753 reads for Agenda, including 549 offset discontinuities. This measures the concrete I/O workload a card backend would inherit, independent of any assumed device bandwidth.

## Step 3 — Complete the hardware pair and deliver the guide

The paired test from Step 1 ran to completion and restored the saved ordinary headless image. The guarded image saved 930.308 seconds for Agenda and 52.084 seconds for Files. Both application modules matched the independently built catalog digests. These runs test the earlier guarded-proof scheduling change; the proposals in this research guide were measured separately and are being implemented in PICOCALC-CJI-TRIE.

### Prompt Context

See Step 1. Commits a74574b and b933ab9 contain the intern guide, source and instruction evidence that preceded physical completion.

### What I did

- Ran script 14 against /tmp/cji-reattach-pair. It revalidated every physical group with PERF script 09 and checked the four GC work counters against independent RV32 receipts for both variants.
- Recorded elapsed and frontend times, GC, module and firmware identities. Verified the ordinary restoration with a terminal Flaky smoke and handed off the serial port to the TRIE experiment.
- Re-read the guide against the evidence. Shortened commands that exceeded the PDF margin and rearranged the proof diagram labels. Generated the final 13-page PDF; both diagrams were embedded, the elapsed-time table survived text extraction, and no extracted word reached the right-page edge.

### Why

The primary outcome is physical job latency. The complete job contains load, link and assembly in addition to frontend analysis. A full-module digest also verifies the final product.

### What worked

Both end-to-end times improved at the same 8 MiB arena cap, with higher live-byte peaks in the guarded run. The full collector work matched emulation across both programs and builds. Remarquee reported “OK: uploaded CJI Intern Guide - Static Types and Sparse Range Analysis.pdf” to /ai/2026/11/18/PICOCALC-CJI-STATIC.

### What didn't work

The first rendered reproduction block had three commands extending to the right edge. PDF text bounding boxes exposed the clipping. Short variables and a shell line continuation fixed it in the delivered edition.

### What I learned

Single-pair physical savings were 63.09% for Agenda and 19.89% for Files. These are close to the independently measured guest instruction reductions, although instruction count alone cannot predict physical time in general.

### What was tricky to build

The firmware used for compiling and the installed application ELF have separate identities. Script 14 checks each against its own reference and checks target memory configuration. The restore run uses the original image, whose identity matches the control.

### What warrants a second pair of eyes

There was one physical measurement per cell. The comparison supports the direction and magnitude for these jobs; estimating trial-to-trial spread requires repeated pairs.

### What should be done in the future

Compare the next candidate to the now-qualified guarded base; changing the reference back to the ordinary build would mix independent effects.
